OVERVIEW
--------------------------------------------------------------------------------
This runbook guides you through a complete disaster recovery from cloud storage
when physical backup drives are lost, destroyed, or inaccessible.

Key Features of Cloud Recovery:
  • No local intermediate storage needed: the BTRFS OS stream is piped directly
    from rclone through zstdcat into btrfs receive in flight.
  • Personal home data is restored by mounting the remote Pika Borg repository
    over rclone mount and extracting directly.

Recovery Flow:
  1. Boot Arch Linux / {{DISTRO}} Live USB and establish internet access
  2. Partition and format replacement drive (EFI + BTRFS root)
  3. Configure rclone and stream download OS image into btrfs receive
  4. Snapshot read-only received clone to writable '@' subvolume
  5. Delete read-only clone subvolume
  6. Recreate subvolume layout based on: {{SUBVOL_LAYOUT}}
  7. Set '@' as default BTRFS subvolume
  8. Mount all subvolumes for chroot
  9. Update all UUIDs in /etc/fstab and bootloader configurations
 10. Chroot and rebuild bootloader ({{BOOTLOADER}})
 11. Mount cloud Pika repo via rclone and restore home directory
 12. Unmount and reboot into fully restored system

--------------------------------------------------------------------------------
STEP 1: BOOT LIVE USB AND ESTABLISH INTERNET CONNECTION
--------------------------------------------------------------------------------
1. Boot your machine from an Arch Linux or {{DISTRO}} Live USB.
2. In the Live environment, open a root terminal.
3. Establish internet connectivity:

   - If using Ethernet: DHCP usually connects automatically.
     Test with: ping -c 3 archlinux.org

   - If using Wi-Fi (via iwd / iwctl):
     iwctl
     station wlan0 scan
     station wlan0 get-networks
     station wlan0 connect "<YOUR_WIFI_SSID>"
     exit

4. Verify network connectivity:

     ping -c 3 archlinux.org

5. Install necessary recovery packages in the Live environment:

     pacman -Sy --needed rclone zstd btrfs-progs borg


--------------------------------------------------------------------------------
STEP 2: PARTITION AND FORMAT NEW NVME / SSD
--------------------------------------------------------------------------------
[WARNING: THIS WILL COMPLETELY ERASE THE TARGET DRIVE]

1. Identify your target drive using lsblk:

     lsblk -o NAME,SIZE,TYPE,FSTYPE,MODEL

   (Assuming target is /dev/NEW_DRIVE; adjust accordingly if /dev/sda or similar).

2. Partition the new drive using cgdisk or parted:

   Option A — Interactive (cgdisk):
     cgdisk /dev/NEW_DRIVE
     - Partition 1: Size: 4096M (4GB), Type: EF00 (EFI System Partition)
     - Partition 2: Size: Remaining space, Type: 8300 (Linux filesystem)
     - Write changes and exit.

   Option B — Scripted (parted):
     parted -s /dev/NEW_DRIVE mklabel gpt
     parted -s /dev/NEW_DRIVE mkpart "EFI" fat32 1MiB 4097MiB
     parted -s /dev/NEW_DRIVE set 1 esp on
     parted -s /dev/NEW_DRIVE mkpart "ROOT" btrfs 4097MiB 100%

3. Format the partitions:

   mkfs.fat -F 32 -n EFI /dev/NEW_EFI_PARTITION
   mkfs.btrfs -f -L ARCH_ROOT /dev/NEW_ROOT_PARTITION

4. Capture new partition UUIDs:

   NEW_EFI_UUID=$(blkid -s UUID -o value /dev/NEW_EFI_PARTITION)
   NEW_ROOT_UUID=$(blkid -s UUID -o value /dev/NEW_ROOT_PARTITION)

   echo "New EFI UUID:  $NEW_EFI_UUID"
   echo "New Root UUID: $NEW_ROOT_UUID"


--------------------------------------------------------------------------------
STEP 3: CONFIGURE RCLONE AND STREAM DOWNLOAD OS IMAGE
--------------------------------------------------------------------------------
1. Mount the new drive's top-level BTRFS root:

   mkdir -p /mnt/new_os
   mount -o subvol=/,compress=zstd /dev/NEW_ROOT_PARTITION /mnt/new_os

2. Set up rclone:

   Option A — If you have your saved rclone.conf (on USB or phone):
     mkdir -p ~/.config/rclone
     cp /path/to/saved/rclone.conf ~/.config/rclone/rclone.conf

   Option B — Run interactive configuration:
     rclone config
     Create a new remote matching: {{CLOUD_REMOTE}} (without trailing colon)

3. Restore your Age private key:
   Retrieve your saved `cloud_os.key` from your password manager and save it:
     nano /root/cloud_os.key
     chmod 600 /root/cloud_os.key

4. Verify access to the cloud OS backup directory:

   rclone lsf {{CLOUD_REMOTE}}{{CLOUD_OS_DIR}}/

5. Restore all subvolumes from the OS cloud clone archives.

We have generated an automated script that will find the latest cloud archives for each
of your system subvolumes ({{SUBVOL_LAYOUT}}), securely stream them, decrypt them, and set them up as writable subvolumes.

[CRITICAL: In-flight streaming avoids requiring double disk space on the new drive]

Run the following block of code in your terminal:

{{CLOUD_RECOVERY_SCRIPT}}
Create snapshot placeholder directories inside the new root:

  mkdir -p /mnt/new_os/{{DETECTED_ROOT_SUBVOL_STR}}/.snapshots
  mkdir -p /mnt/new_os/{{DETECTED_ROOT_SUBVOL_STR}}/.snapshots_btrbk
  chmod 750 /mnt/new_os/{{DETECTED_ROOT_SUBVOL_STR}}/.snapshots


--------------------------------------------------------------------------------
STEP 4: SET '{{DETECTED_ROOT_SUBVOL_STR}}' AS BTRFS DEFAULT SUBVOLUME
--------------------------------------------------------------------------------
Find the subvolume ID of '{{DETECTED_ROOT_SUBVOL_STR}}' and set it as the default:

  ROOT_SUBVOL_ID=$(btrfs subvolume list /mnt/new_os | grep ' path {{DETECTED_ROOT_SUBVOL_STR}}$' | awk '{print $2}')
  echo "Setting default subvolume to ID: $ROOT_SUBVOL_ID"
  btrfs subvolume set-default "$ROOT_SUBVOL_ID" /mnt/new_os

Unmount the top-level mount point:

  umount /mnt/new_os


--------------------------------------------------------------------------------
STEP 5: MOUNT ALL SUBVOLUMES FOR CHROOT
--------------------------------------------------------------------------------
Mount '{{DETECTED_ROOT_SUBVOL_STR}}' as the root filesystem:

  mkdir -p /mnt/target
  mount -o subvol={{DETECTED_ROOT_SUBVOL_STR}},compress=zstd /dev/NEW_ROOT_PARTITION /mnt/target

Create mount points for nested subvolumes:

{{SUBVOL_MKDIR_CMDS}}
Mount the corresponding subvolumes:

{{SUBVOL_MOUNT_CMDS}}
Mount the new EFI partition:

  mkdir -p /mnt/target{{EFI_MOUNT_PATH}}
  mount /dev/NEW_EFI_PARTITION /mnt/target{{EFI_MOUNT_PATH}} 2>/dev/null


--------------------------------------------------------------------------------
STEP 6: UPDATE ALL UUIDs IN CONFIGURATION FILES [CRITICAL]
--------------------------------------------------------------------------------
[CRITICAL WARNING: DRIVE UUID MISMATCH]
Original Root UUID: {{ROOT_UUID}}
Original EFI UUID:  {{EFI_UUID}}
New Root UUID:      $NEW_ROOT_UUID
New EFI UUID:       $NEW_EFI_UUID

1. Update /mnt/target/etc/fstab:
   sed -i "s/{{ROOT_UUID}}/$NEW_ROOT_UUID/g" /mnt/target/etc/fstab
   sed -i "s/{{EFI_UUID}}/$NEW_EFI_UUID/g" /mnt/target/etc/fstab

   Verify fstab contents:
   cat /mnt/target/etc/fstab

2. Update bootloader configurations:

   - If Limine:
     sed -i "s/{{ROOT_UUID}}/$NEW_ROOT_UUID/g" /mnt/target/etc/default/limine 2>/dev/null || true
     sed -i "s/{{ROOT_UUID}}/$NEW_ROOT_UUID/g" /mnt/target/boot/limine*.cfg 2>/dev/null || true
     sed -i "s/{{ROOT_UUID}}/$NEW_ROOT_UUID/g" /mnt/target/boot/limine*.conf 2>/dev/null || true

   - If GRUB:
     sed -i "s/{{ROOT_UUID}}/$NEW_ROOT_UUID/g" /mnt/target/etc/default/grub 2>/dev/null || true

   - If systemd-boot:
     sed -i "s/{{ROOT_UUID}}/$NEW_ROOT_UUID/g" /mnt/target/boot/loader/entries/*.conf 2>/dev/null || true


--------------------------------------------------------------------------------
STEP 7: CHROOT AND REBUILD BOOTLOADER ({{BOOTLOADER}})
--------------------------------------------------------------------------------
1. Enter the chroot environment:

     arch-chroot /mnt/target

2. Regenerate initramfs image:

     mkinitcpio -P

3. Rebuild bootloader according to: {{BOOTLOADER}}

   - If Limine:
       limine-mkinitcpio

   - If GRUB:
       grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB --recheck
       grub-mkconfig -o /boot/grub/grub.cfg

   - If systemd-boot:
       bootctl --path=/boot install


--------------------------------------------------------------------------------
STEP 8: RESTORE HOME DATA FROM CLOUD PIKA / BORG REPO
--------------------------------------------------------------------------------
The OS clone restored the base system and applications. Personal data
(/home/{{USERNAME}}) is stored in your cloud Borg repository at:
{{CLOUD_REMOTE}}{{CLOUD_PIKA_DIR}}

1. Outside or inside chroot, mount the cloud repository using rclone:

   mkdir -p /mnt/cloud_repo
   rclone mount {{CLOUD_REMOTE}}{{CLOUD_PIKA_DIR}} /mnt/cloud_repo --daemon

   Wait a few seconds for the mount to establish:
   sleep 3
   ls -la /mnt/cloud_repo

2. Locate your Borg repository:
   Depending on whether the entire repository was synced or a subfolder:
   REPO_PATH="/mnt/cloud_repo"
   [ -d "/mnt/cloud_repo/backup-{{HOSTNAME_VAL}}-{{USERNAME}}" ] && \
     REPO_PATH="/mnt/cloud_repo/backup-{{HOSTNAME_VAL}}-{{USERNAME}}"

3. List available archives in the Borg repository:

   borg list "$REPO_PATH"

4. Extract files into the target root filesystem (Borg stores paths as 'home/{{USERNAME}}/...'):

   cd /mnt/target 2>/dev/null || cd /
   borg extract --progress "$REPO_PATH::<ARCHIVE_NAME>"

5. Restore correct user ownership:

   chown -R {{USERNAME}}:{{USERNAME}} /mnt/target/home/{{USERNAME}} 2>/dev/null || \
   chown -R {{USERNAME}}:{{USERNAME}} /home/{{USERNAME}}

6. Unmount the cloud repository:

   fusermount -u /mnt/cloud_repo 2>/dev/null || umount /mnt/cloud_repo 2>/dev/null || true


--------------------------------------------------------------------------------
STEP 9: CLEANUP AND REBOOT
--------------------------------------------------------------------------------
1. Exit chroot if still inside:

     exit

2. Unmount all target partitions:

     umount -R /mnt/target

3. Reboot:

     reboot

4. Remove the Live USB. Your system should boot into your restored Arch Linux environment.
